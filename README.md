# ケース・コーチ ローカル版

症例報告・スライドの壁打ちと、事例振り返りの支援を、**利用者のPC内で動くAI（ローカルLLM）だけ**で行うWebアプリです。
画面は GitHub Pages から配布し、入力した文章やファイルはPCの外に出ません。

| ツール | 元にしたGem | 直接開くURL |
|---|---|---|
| 症例報告・スライド壁打ち | 学会症例報告、スライド壁打ちサポート | `…/case-coach-local/#case` |
| 事例振り返り | 事例振り返りサポート | `…/case-coach-local/#reflection` |

---

## 入力がPCの外に出ない仕組み

```
 GitHub Pages ── 画面の部品（HTML/JS/CSS）だけを配信 ──▶ ブラウザ
                                                          │
                              入力・ファイル・AIの返答は    │  http://localhost:11434
                              この区間（PC内）だけを流れる  ▼
                                                   Ollama / LM Studio（同じPC）
```

- **サーバー側の処理はありません。** 配布しているのは静的ファイルだけです。
- **通信先をブラウザが制限します。** `index.html` の Content-Security-Policy で、通信できる先を「このサイト自身」と「`localhost` / `127.0.0.1`」に限定しています。外部のライブラリ・フォント・アクセス解析も読み込みません（PDF読み取り用の pdf.js も同梱）。
- **ファイルの解析もブラウザ内です。** .pptx / .docx はブラウザ標準の解凍機能、PDF は同梱の pdf.js で読みます。
- **入力内容は保存しません。** ブラウザに保存するのは接続設定と、利用者が編集したプロンプトだけです。対話を残したいときは「記録を書き出す（.md）」「作業を保存（.json）」で利用者のPCにファイルとして保存します。

知っておくべき限界：

- GitHub はページを配信するため、アクセス元のIPアドレスなどの一般的なアクセス記録を持ちます（入力内容は含まれません）。
- `hm-cmed.github.io` 配下のページは同じ保存領域（localStorage）を共有します。本アプリは設定しか保存せず、キー名に `casecoach.` を付けて区別しています。
- ブラウザの拡張機能はページの内容を読める場合があります。共用PCでは使い終わったらタブを閉じてください。

## 公開する（管理者向け・初回のみ）

ビルド作業は不要です。このフォルダの中身をそのまま置くだけで動きます。

1. GitHub で新しいリポジトリを作る（例：`hm-cmed/case-coach-local`）。
2. このフォルダの中身（`index.html`、`assets/`、`vendor/`、`.nojekyll` など）をリポジトリ直下に置いて push する。
3. リポジトリの **Settings → Pages** で「Deploy from a branch」→ `main` / `(root)` を選んで保存する。
4. 数分後に `https://hm-cmed.github.io/case-coach-local/` で開けるようになります。

利用者が Ollama に許可するアドレスは **`https://hm-cmed.github.io`**（末尾のパスは付けない）です。アプリの「準備と使い方」には、開いているページのアドレスに合わせたコマンドが自動で表示されます。

### 公開前に手元で試す

```powershell
cd case-coach-local
python -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開きます。Ollama は `localhost` からの接続を最初から許可しているので、下の手順3は不要です。
（`index.html` をダブルクリックで開く方法では動きません。必ず上のようにサーバー経由で開いてください。）

## 利用者の準備（Windows・初回のみ）

1. **Ollama を入れる** — https://ollama.com から Windows 版をインストール。
2. **モデルを取得する** — PowerShell で
   ```powershell
   ollama pull gemma3:12b
   ```
   メモリ16GB程度なら `gemma3:12b`（画像も読めるのでスライドPDFの見た目も評価できる）、8GB程度なら `gemma3:4b` が目安です。日本語に強い新しいモデルがあれば、それでも動きます。
3. **このサイトからの接続を許可する** — PowerShell で
   ```powershell
   [Environment]::SetEnvironmentVariable("OLLAMA_ORIGINS", "https://hm-cmed.github.io", "User")
   ```
   タスクバー右下（「^」の中）の Ollama アイコンを右クリック →「Quit Ollama」→ **スタートメニューから**起動し直す（この再起動をしないと設定が効きません）。
   すでに `OLLAMA_ORIGINS` を使っている場合は、上書きせずカンマ区切りで追記してください。
   確かめ方：`curl.exe -i -H "Origin: https://hm-cmed.github.io" http://localhost:11434/api/tags` の1行目が `HTTP/1.1 200 OK` なら許可済み、`HTTP/1.1 403 Forbidden` なら未設定か再起動前。
4. **ブラウザの許可** — Chrome / Edge で「ローカルネットワーク上のデバイスへのアクセス」の許可を求められたら「許可」。
5. **つなぐ** — アプリ右上の「設定」→「接続を確かめる」→ モデルを選ぶ。つながらないときは「Ollama が動いている／このサイトを許可している／モデルがある」の3段階で、どこで止まっているかと直し方が表示されます。

アドレスの `11434` は Ollama の標準の番号です。Ollama の設定（`OLLAMA_HOST`）で変えていない限り、変更は不要です。

Mac は手順3を `launchctl setenv OLLAMA_ORIGINS "https://hm-cmed.github.io"` に置き換えます（再起動のたびに必要）。

**LM Studio を使う場合**：Developer 画面でサーバーを起動し「Enable CORS」をオン。アプリの設定で「LM Studio など（OpenAI互換）」を選び、アドレスを `http://localhost:1234` にします。

推奨ブラウザは Chrome / Edge です。

## 中身を変える

### プロンプトと評価基準：`assets/prompts.js`

Gem の「カスタム指示」に当たる部分です。ここを編集して push すると、全利用者の既定値が変わります。

- `CASE_SYSTEM_TEMPLATE` / `REFLECTION_SYSTEM_TEMPLATE` … 指示文本体
- `RUBRICS` … 抄録7項目・スライド8項目の配点と「高得点／低得点の目安」
- `RANKS` … A〜D の境界（80 / 65 / 50）
- `COMPETENCIES` … 振り返りで選べる資質・能力（総合診療専門医の7つ。所属プログラムの定義に合わせて変更可）
- `QUICK_ACTIONS` … 対話欄の下のワンクリック依頼

利用者は画面の「設定 → プロンプト」でも指示文を変えられます（その人のブラウザにだけ保存）。

### Gem の「知識」ファイルについて

今回の Gem 書き出しファイルには、2つの Gem の知識ファイル（`deep-research-report (8).md` / `(9).md`）の**リンクだけ**があり、本文は含まれていませんでした。代わりの評価基準は `prompts.js` に明文化してあります。元の資料を使う場合は、次のどちらかで取り込めます。

- 全員に反映：資料の要点を `prompts.js` の指示文に書き足す。
- 自分だけ：「設定 → プロンプト → 参考資料（ナレッジ）」でファイルを読み込む（.md / .txt / .pdf / .docx）。

長い資料はそのぶんAIが一度に読める量を使います。要点に絞るのがおすすめです。

### 研究室・病院内のGPUサーバーにつなぐ

`index.html` の CSP（`connect-src`）と `assets/engines.js` の `LOCAL_HOSTS` に、そのサーバーのアドレスを追加します。
この場合、データは「PCの外に出ない」ではなく「院内ネットワークの外に出ない」になるので、画面の説明文（`index.html` の「このPCの外には送られません」など）も合わせて直してください。

## Gem からの主な変更点

ローカルLLMはクラウドの大規模モデルより小さいため、ぶれやすい部分をアプリ側で補っています。

- **評価基準を明文化**：各項目に配点と「高得点／低得点の目安」を付け、採点の物差しを固定。
- **合計点とランクはアプリが計算**：AIには項目ごとの点だけを決まった書式で出させ、足し算はアプリが行う。AIの申告した合計と食い違えば表示で知らせる。
- **数える作業はアプリが担当**：文字数、字数上限との差、スライド枚数、1分あたり枚数、1枚あたり文字数、発表者ノートの読み上げ時間（毎分300字換算）を計測してAIに渡す。
- **文献の書誌情報を作らせない**：著者名・年などは挙げず、調べるべき文献の種類と検索語を示させる。
- **振り返りの見える化**：Gibbs のリフレクティブ・サイクル6段階と Hatton & Smith の4水準で内省の深さを示す。代筆はせず、2回目以降の問いは1つずつ。
- **個人情報の簡易チェック**：日まで含む日付、ID、人名らしき語、医療機関名、住所、電話番号などを検出し、ワンクリックで伏せ字にできる（目安であり網羅は保証しない）。
- **再評価**：直した版を送ると、前回との点数差を項目ごとに表示。

## ファイル構成

```
index.html          画面の骨組みと通信制限（CSP）
assets/app.js       画面の動き、送信、表示、書き出し
assets/prompts.js   指示文・評価基準・ワンクリック依頼（編集するのは主にここ）
assets/engines.js   Ollama / OpenAI互換サーバーとの通信
assets/extract.js   .pptx / .docx / .pdf / .txt の読み取りと計測
assets/privacy.js   個人情報らしき語のチェックと伏せ字
assets/scores.js    点数表・内省の深さの読み取りと再計算
assets/markdown.js  AIの返答の表示（HTMLを実行しない安全な変換）
assets/style.css    デザイン
vendor/pdfjs/       pdf.js 3.2.146（Mozilla, Apache-2.0）と日本語用 CMap
```

## 既知の制限

- 小さいモデルは点数表の書式を守れないことがあります。そのときは「再生成」を押すか、大きめのモデルに替えてください。
- .pptx から読めるのは文字・発表者ノート・画像の数までです。スライドの見た目も評価したいときは PDF に書き出して読み込み、画像を読めるモデル（例：gemma3）を使います。
- 古い形式（.ppt / .doc）は読めません。
- AIの評価は練習用の目安です。学会の正式な査読や、指導医による評価・臨床判断に代わるものではありません。
